# How Coding Agents Fail on Security-Critical Auth Code — and What Measurably Reduces Those Failures

> **Ticket:** `slovakian/butter#88` (child of Wayfinder map `#86`)
> **Domain terms:** **Butter** (the opinionated auth guide, reference implementations, and agent tooling published by this repo); **target auth system** (the bespoke auth code an agent builds and maintains inside a team's own app).

## 1. Executive Summary

Empirical security benchmarks from 2022–2026 converge on a stark finding: **functional correctness in agent-generated code does not imply security, and the gap is widest in security-critical backend code such as authentication, authorization, and session handling.**

- **Half to four-fifths of functionally passing code is exploitable:** Across flagship models on backend application benchmarks (**BaxBench**, 392 tasks across 14 frameworks), security exploits succeed on **~50%** of functionally passing backends ([Vero et al., 2025](https://arxiv.org/abs/2502.11844)). On real-world repository feature tasks (**SusVibes**, 186 tasks across 100 repositories), SWE-agent + Claude 4 Sonnet achieved **57.0% functional pass** (`FuncPass`) but only **11.8% secure pass** (`SecPass`) — **79.3% of functionally passing solutions were vulnerable** ([Zhao et al., 2025](https://arxiv.org/abs/2512.03262)).
- **Prose rules files and security reminders alone fail as guardrails:** Adding security reminders or CWE self-identification checklists yields tiny security gains (+2.7 to +3.3 pp on SusVibes; +1.6 pp on repository-scale SecRepoBench) while often *reducing* functional pass rates ([Zhao et al., 2025](https://arxiv.org/abs/2512.03262); [Shen et al., 2025](https://arxiv.org/abs/2504.21205)). Repository markdown rules files (`AGENTS.md`) act as non-binding advice rather than enforcement gates ([Dhuri, 2026](https://arxiv.org/abs/2611.27112)), and overloaded skills introduce task-implementation faults ([Dong et al., 2026](https://arxiv.org/abs/2608.11888)).
- **Fast-moving and lower-resource stacks compound security failures:** On BaxBench, less ubiquitous frameworks suffer both lower correctness and a higher share of vulnerabilities ([Vero et al., 2025](https://arxiv.org/abs/2502.11844)). On version-conditioned API tasks (**GitChameleon**), GPT-4o scored only **39.9% `pass@10`** due to cross-version API drift ([Islah et al., 2024](https://arxiv.org/abs/2411.05830)), while commercial models hallucinate **5.2%** of package names (open-source models: **21.7%**) ([Spracklen et al., 2025](https://arxiv.org/abs/2406.10279)). This directly threatens a target auth system built with **Effect v4** and **Reylo**.
- **What measurably works:** Four layered mechanisms show empirical gains: (1) **secure-by-construction APIs and type-level invariants** that make insecure states unrepresentable ([Kern, 2014](https://research.google/pubs/securing-the-tangled-web/); [Kern, 2024](https://doi.org/10.1145/3651621)), (2) **pinned, runnable reference implementations and compact, focused skills (≤3 modules)** grounded in exact library versions ([Li et al., 2026](https://arxiv.org/abs/2602.12670); [Islah et al., 2024](https://arxiv.org/abs/2411.05830)), (3) **executable conformance and adversarial security test suites** that the coding agent cannot weaken or self-grade ([Vero et al., 2025](https://arxiv.org/abs/2502.11844); [Wang et al., 2024](https://arxiv.org/abs/2407.02395)), and (4) **structured multi-pass review plus targeted static analysis (SAST)** as a secondary net for syntactic crypto/injection flaws ([Shen et al., 2025](https://arxiv.org/abs/2504.21205); [Nazzal et al., 2024](https://arxiv.org/abs/2409.12699)).

## 3. Concrete Agent Failure Modes in Auth & Session Code

Drawing directly from BaxBench Table 6, SusVibes' CWE taxonomy and qualitative case studies, CyberSecEval, Perry et al., and normative specs (IETF RFC 9700, OWASP ASVS, and the Copenhagen Book), coding agents fail predictably across ten auth/session failure classes:

### 3.1 Timing Leaks & Side-Channel Account Enumeration (`CWE-208`, `CWE-203`)
- **Failure pattern:** Agents compare session tokens, HMACs, CSRF tokens, or reset hashes with `===` / `==` (short-circuiting at the first differing byte) instead of constant-time primitives (`crypto.timingSafeEqual`). Worse, on login flows they return early when a user does not exist or has an unusable/OAuth-only password, skipping password verification entirely.
- **Primary evidence:** SusVibes ([Zhao et al., 2025, §4.3](https://arxiv.org/abs/2512.03262)) directly documents SWE-agent + Claude 4 Sonnet re-implementing Django's `verify_password()`: the agent passed every functional test but omitted the dummy/fake hash verification path for `None`/unusable passwords, returning immediately and opening a timing oracle for username enumeration (`CWE-208` / `CWE-203`). Both [OWASP ASVS](https://owasp.org/www-project-application-security-verification-standard/) and [The Copenhagen Book](https://thecopenhagenbook.com/) explicitly require constant-time comparison and uniform error/timing behavior across login, registration, and password reset.

### 3.2 Insufficiently Protected Credentials & Weak Crypto Defaults (`CWE-522`, `CWE-916`, `CWE-327`, `CWE-328`, `CWE-330`, `CWE-338`, `CWE-798`)
- **Failure pattern:** Storing plaintext session tokens or reset tokens in the database (rather than storing their cryptographic hash); hashing passwords with fast hashes (SHA-256/MD5) or weak KDF parameters; truncating passwords silently at 72 bytes with `bcrypt`; generating tokens with non-cryptographic `Math.random()` instead of CSPRNG (`crypto.getRandomValues` / `crypto.randomBytes`); hardcoding fallback JWT/signing secrets (`process.env.JWT_SECRET || "dev-secret"`); accepting weak or attacker-chosen JWT algorithms (`CWE-347`).
- **Primary evidence:** In BaxBench Table 6 (no security reminder), functionally passing backends exhibited **CWE-522 (Insufficiently Protected Credentials)** in **100%** of `SecretStorage` apps, **94%** of `UptimeService` apps, **17%** of `UserCreation` apps, **16%** of `ShopOverview` apps, and **11%** of `Login` apps ([Vero et al., 2025, Appendix D.2](https://arxiv.org/abs/2502.11844)). Perry et al. found AI-assisted developers achieved only **3%** secure implementations on ECDSA signing (vs 21% control) and **~21%** on symmetric encryption (vs ~43% control), largely from legacy defaults and library misuse ([Perry et al., 2023](https://arxiv.org/abs/2211.03622)). CyberSecEval and Veracode 2025 both highlight persistent `CWE-327`/`CWE-328`/`CWE-338` and `CWE-798` generation across models ([Bhatt et al., 2023](https://arxiv.org/abs/2312.04724); [Veracode, 2025](https://www.veracode.com/resources/analyst-reports/2025-genai-code-security-report/)).

### 3.3 Broken CSRF & Cookie / `SameSite` Handling (`CWE-352`, `CWE-614`, `CWE-1004`, `CWE-1275`)
- **Failure pattern:** Omitting `HttpOnly`, `Secure`, or `SameSite` cookie attributes (especially in local-dev-friendly code that never tightens for production); assuming `SameSite=Lax` alone eliminates all CSRF (ignoring cross-subdomain attacks, sibling-domain cookie tossing, `GET` state-mutation endpoints, or non-standard content-type handling) and omitting `Origin`/`Host` header verification or CSRF tokens; failing to bind OAuth `state` cookies with `HttpOnly` + `SameSite=Lax`.
- **Primary evidence:** Both `CWE-352` (CSRF) and `CWE-614` (Sensitive Cookie Without `Secure` Attribute) are recurring OWASP A01/A02 failure classes in SusVibes ([Zhao et al., 2025, Appendix A](https://arxiv.org/abs/2512.03262)). The Copenhagen Book explicitly warns that `SameSite=Lax` is a baseline layer that must be paired with `Origin` checking or anti-CSRF tokens on state-changing requests ([The Copenhagen Book](https://thecopenhagenbook.com/)).

### 3.4 Session Fixation, Lifecycle & Redirect Header Injection (`CWE-384`, `CWE-613`, `CWE-601`, `CWE-93`)
- **Failure pattern:** Reusing a pre-authentication session ID across login or privilege elevation instead of issuing a fresh session token (`CWE-384`); missing sliding idle expiry + hard absolute expiry (`CWE-613`); failing to revoke all active sessions on password change/reset; persisting bearer tokens in `localStorage` where any XSS exfiltrates them; allowing unvalidated post-login `redirect_to` / `next` URLs (`CWE-601` open redirect or CRLF header injection).
- **Primary evidence:** SusVibes ([Zhao et al., 2025, Appendix D, Additional Case One](https://arxiv.org/abs/2512.03262)) documents a frontier agent implementing Buildbot's authentication/OAuth2 redirect layer without stripping `\r\n` (`protect_redirect_url()`), enabling CRLF injection of `Set-Cookie: SESSION=attacker` directly into the HTTP response — a textbook session-fixation primitive. OWASP ASVS and the Copenhagen Book mandate regenerating session identifiers on every authentication state transition and strictly allow-listing relative redirect paths.

### 3.5 Missing/Broken Authorization & Multi-Tenant IDOR (`CWE-284`, `CWE-306`, `CWE-639`, `CWE-862`, `CWE-863`)
- **Failure pattern:** Authenticating *who* the caller is while forgetting to check *whether* they own the target record or belong to the target organization in SQL `WHERE` clauses (`CWE-639` / `CWE-863`); adding new endpoints that bypass auth middleware (`CWE-306`); trusting client-supplied `userId` or `orgId` fields instead of deriving them strictly from the verified session.
- **Primary evidence:** In BaxBench Table 6, **51%** of functionally passing `SecretStorage` backends failed **CWE-284 (Improper Access Control)** and **5%** of `Unsubscribe` backends failed **CWE-863** ([Vero et al., 2025, Appendix D.2](https://arxiv.org/abs/2502.11844)). Broken Access Control (`CWE-284`, `CWE-285`, `CWE-639`, `CWE-863`) is the broadest CWE family in SusVibes (14 CWEs under OWASP A01; [Zhao et al., 2025, Appendix A](https://arxiv.org/abs/2512.03262)).

### 3.6 Race Conditions / TOCTOU on Single-Use Tokens & Rate Limits (`CWE-362`, `CWE-367`)
- **Failure pattern:** Implementing single-use credential operations (email verification tokens, magic links, password reset tokens, OAuth authorization codes, refresh-token rotation, and login rate limiters) as two non-atomic queries (`SELECT ... WHERE used_at IS NULL` in app code, followed by `UPDATE ... SET used_at = NOW()`). Under concurrent requests, two callers pass the `SELECT` check simultaneously and redeem the same token twice — breaking single-use guarantees and refresh-token replay detection.
- **Primary evidence:** `CWE-362` (Concurrent Execution using Shared Resource with Improper Synchronization) is explicitly tracked in SusVibes under OWASP A06 Insecure Design ([Zhao et al., 2025, Appendix A](https://arxiv.org/abs/2512.03262)), and RFC 9700 §4 mandates strict single-use enforcement and replay revocation for OAuth authorization codes and rotated refresh tokens ([Lodderstedt et al., RFC 9700, 2025](https://www.rfc-editor.org/rfc/rfc9700)). In PostgreSQL, the safe pattern is an atomic conditional mutation (`UPDATE ... WHERE token_hash = $1 AND consumed_at IS NULL AND expires_at > NOW() RETURNING ...` or `DELETE ... RETURNING ...`) rather than read-then-write.

### 3.7 OAuth 2.0 / OIDC Protocol Pitfalls (`CWE-347`, `CWE-352`, `CWE-601`, `CWE-287`)
- **Failure pattern:** Implementing legacy Implicit/ROPC flows or omitting **PKCE (`S256`)** for confidential web clients; omitting or skipping constant-time verification of the session-bound `state` parameter (enabling Login CSRF); using substring/prefix matching on `redirect_uri` instead of exact matching; failing to validate ID token `iss`, `aud`, `exp`, and `nonce`; auto-linking OAuth accounts by unverified `email` claims (enabling pre-hijacking account takeover).
- **Primary evidence:** **IETF RFC 9700 (BCP 240, Jan 2025)** codifies these exact flaws as the primary real-world OAuth 2.0 attack vectors, mandating PKCE for all clients, exact `redirect_uri` matching, single-use codes with replay revocation, and CSRF binding ([Lodderstedt et al., RFC 9700, 2025](https://www.rfc-editor.org/rfc/rfc9700)).

## 4. Stale API Hallucinations & Fast-Moving Library Misuse

For Butter — whose official reference code targets **Effect v4 (including Effect Schema)** and **Reylo** on PostgreSQL — library novelty and version churn create a **security multiplier**, not just a compilation nuisance:

1. **Lower-resource frameworks suffer higher vulnerability shares, not just lower correctness:** BaxBench ([Vero et al., 2025, §4](https://arxiv.org/abs/2502.11844)) proved that when models work in less ubiquitous or more complex frameworks (e.g., Rust-Actix, PHP-Lumen), not only does `pass@1` drop, *even the functionally passing programs contain a higher proportion of exploitable vulnerabilities*.
2. **Version-switching and cross-version API drift:** **GitChameleon** ([Islah et al., 2024, arXiv:2411.05830](https://arxiv.org/abs/2411.05830)) showed that frontier models fail badly when conditioned on specific library versions — GPT-4o scored only **39.9% `pass@10`** (rising only to **43.7%** with execution error feedback). Models blend pre-cutoff major-version idioms (e.g., Effect v3 `Effect.Tag` / `Schema` / `@effect/sql` APIs or legacy auth libraries like Lucia v2/v3 and NextAuth v4) into v4 code, silently dropping error channels, misconfiguring SQL parameterization, or falling back to hand-rolled unsafe workarounds when an unfamiliar API fails to type-check.
3. **Package hallucination & slopsquatting:** **Spracklen et al.** (USENIX Security 2025, [arXiv:2406.10279](https://arxiv.org/abs/2406.10279)) analyzed 576,000 samples across 16 LLMs and found **5.2%** hallucinated packages in commercial models and **21.7%** in open-source models (**205,474 unique fabricated package names**). When an agent tries to invent a helper package (e.g., `@reylo/auth` or `effect-argon2`), it either breaks builds or opens a **slopsquatting** supply-chain vector.
4. **Measured fix for API drift:** Grounding the model with pinned, version-accurate reference docs/code via retrieval lifts version-conditioned accuracy by roughly **~10 percentage points** on GitChameleon ([Islah et al., 2024](https://arxiv.org/abs/2411.05830)) — meaning Butter's pinned, CI-verified Effect v4 + Reylo reference modules are a direct security control, not mere documentation.

## 5. Evidence-Backed Interventions: What Measurably Works vs. What Fails

| Intervention | Primary Evidence & Measured Effect | Strengths & Blind Spots |
| :--- | :--- | :--- |
| **Prose rules files (`AGENTS.md` / `.cursorrules`) & generic security reminders** | **Weak / sometimes harmful.** SusVibes: generic prompt left `SecPass` at **11.8%**; 2-phase CWE self-selection gave **+2.7 pp** (`14.5%`) at a **-7.0 pp** `FuncPass` cost; even *oracle* CWE hints reached only **15.1%** `SecPass` ([Zhao et al., 2025, Table 5](https://arxiv.org/abs/2512.03262)). SecRepoBench: policy prompts added only **+1.6 pp** `secure-pass@1` at repo scale ([Shen et al., 2025](https://arxiv.org/abs/2504.21205)). *"Markdown Is Not a Firewall"*: a 278-word rules file dropped pooled hidden-test pass rates from **98.2% → 90.9%** (Codex CLI: **99.0% → 67.7%**, falsely reporting all tests passing in 11/36 steps because its *own* tests passed) ([Dhuri, 2026](https://arxiv.org/abs/2611.27112)). | Rules files are non-binding advice, not an enforcement boundary. Useful for stating conventions, useless as a firewall. |
| **Compact, focused Skills (≤3 modules) + pinned reference implementations** | **Strong for correctness & API grounding; dangerous when bloated.** **SkillsBench** (87 tasks, 18 model-harness configs): curated Skills raised average pass rate from **33.9% → 50.5%** (**+16.6 pp**), with focused skills (≤3 modules) outperforming exhaustive bundles ([Li et al., 2026](https://arxiv.org/abs/2602.12670)). Conversely, *"Agent Skills Can Be Harmful"* confirmed **307 skill-induced failures** (125 functional, 182 efficiency regressions), where **68.8%** (86/125) of functional failures came from seemingly relevant skills causing agents to omit/misimplement required fields or domain rules ([Dong et al., 2026](https://arxiv.org/abs/2608.11888)). On GitChameleon, pinned version docs raised pass rates by **~10 pp** ([Islah et al., 2024](https://arxiv.org/abs/2411.05830)). | Ship small, modular, copyable, CI-verified Effect v4 + Reylo reference slices instead of monolithic prose manuals. |
| **Type-level guardrails & secure-by-construction APIs** | **Eliminates entire vulnerability classes structurally.** Google's *Safe Coding* research ([Kern, 2014](https://research.google/pubs/securing-the-tangled-web/); [Kern, 2024, CACM](https://doi.org/10.1145/3651621)) demonstrates at scale that replacing unconstrained primitive APIs (raw strings, ambient authority) with strictly typed safe primitives shifts security invariants from developer/agent vigilance to compile-time enforcement. | Prevents `===` on raw secrets, unhashed token storage, missing auth middleware (`AuthenticatedSession` required in Effect `Context`), and non-atomic SQL writes — cannot be "forgotten" by an agent under context pressure. |
| **Executable conformance & adversarial security test suites** | **Highest-leverage dynamic gate.** BaxBench, SecCodePLT, CWEval, and SusVibes all show that agents only reliably satisfy properties backed by executable tests ([Vero et al., 2025](https://arxiv.org/abs/2502.11844); [Nie et al., 2024](https://arxiv.org/abs/2410.11096); [Peng et al., 2025](https://arxiv.org/abs/2501.08200)). **SecAwareCoder** (task-adaptive threat modeling + **security-aware test synthesis** + execution feedback) raised GPT-5 on CodeSecEval from **46.28% F-Pass@1 / 25.10% S-Pass@1** (Greedy) to **54.90% F-Pass@1 / 34.90% S-Pass@1** (**+9.8 pp** security *while simultaneously raising* functionality by **+8.6 pp**) ([Wang et al., 2024, Table 4](https://arxiv.org/abs/2407.02395)). | Tests must be **immutable / pre-authored** (shipped by Butter as an executable conformance & exploit suite), because agents cannot be trusted to self-grade security with tests they wrote ([Dhuri, 2026](https://arxiv.org/abs/2611.27112)). |
| **Multi-pass security review & Recursive Criticism (RCI)** | **Measurable incremental lift.** Tony et al. found Recursive Criticism and Improvement (RCI) systematically reduced CWEs over zero-shot prompting across GPT-3/3.5/4 ([Tony et al., 2024](https://arxiv.org/abs/2407.07064)). On **SecRepoBench**, adding an explicit review pass to Codex + GPT-5.1-Codex-Max lifted `secure-pass@1` from **56.3% → 60.1%** (**+3.8 pp**) while nudging `pass@1` up (`75.8% → 76.4%`) ([Shen et al., 2025](https://arxiv.org/abs/2504.21205)). | Best run as a separate fresh-context adversarial pass checking a concrete auth threat checklist, paired with tests — never as the sole gate. |
| **Static Analysis (SAST) in the loop** | **High recall on syntactic bugs; blind to auth logic.** CodeQL/Semgrep/Bandit feedback loops (e.g., PromSec, Code Shield) dramatically reduce syntactic CWEs like weak crypto (`CWE-327`), hardcoded secrets (`CWE-798`), SQLi (`CWE-89`), and missing cookie flags ([Nazzal et al., 2024](https://arxiv.org/abs/2409.12699); [Bhatt et al., 2023](https://arxiv.org/abs/2312.04724)). However, CWEval proves SAST has substantial false negatives and false positives on slight semantic variations ([Peng et al., 2025, Fig. 1](https://arxiv.org/abs/2501.08200)), and SAST routinely misses IDOR, missing auth checks, timing fake-paths, session fixation, and TOCTOU races. | Worth including as a fast CI lint layer (e.g., custom Semgrep/lint rules banning `===` on tokens, `Math.random()`, `localStorage` session writes, or unparameterized SQL), but **cannot** replace executable security tests. |

## 6. Concrete Design Implications for Butter v1

Synthesizing the evidence directly against Butter's architecture (Effect v4 + Effect Schema + Reylo on PostgreSQL, consumed by coding agents to build a team's target auth system):

1. **Treat Butter's reference code and type signatures — not prose rules — as the primary security boundary.**
   - Encode invariants in Effect v4 types: opaque/branded `RawToken` vs `TokenHash` (preventing raw token storage `CWE-522`), an `AuthenticatedUser` / `ActiveSession` Effect service required by protected handlers (preventing missing auth `CWE-306`), typed domain error channels that map to uniform external HTTP responses (preventing enumeration `CWE-203`), and atomic Reylo PostgreSQL queries (`UPDATE ... WHERE consumed_at IS NULL RETURNING ...`) for every single-use token (preventing TOCTOU `CWE-362`).
2. **Ship a pre-authored, executable Auth Conformance & Adversarial Test Suite.**
   - Because agents pass functional tests while shipping exploitable auth bugs ~50%–80% of the time ([Vero et al., 2025](https://arxiv.org/abs/2502.11844); [Zhao et al., 2025](https://arxiv.org/abs/2512.03262)) and cannot reliably self-grade ([Dhuri, 2026](https://arxiv.org/abs/2611.27112)), Butter should provide runnable negative/exploit tests that teams run against their target auth system in CI:
     - Concurrent token-redemption race tests (20 parallel requests redeeming the same reset/verification/refresh token → exactly 1 succeeds).
     - Session fixation tests (pre-login session cookie is invalidated and rotated on login).
     - Cookie & CSRF tests (`HttpOnly`, `Secure`, `SameSite`, mismatched `Origin` rejection on state-changing routes).
     - Enumeration & timing tests (identical status/body and dummy hash execution for unknown emails / unusable passwords).
     - OAuth tests (missing/mismatched `state`, missing PKCE `code_verifier`, disallowed `redirect_uri`, unverified email linking).
     - Tenant/ownership IDOR tests (authenticated User A attempting to read/mutate User B's sessions or resources).
3. **Keep agent-facing guidance modular, compact (≤3 focused modules per workflow), and pinned to exact Effect v4 + Reylo versions.**
   - SkillsBench ([Li et al., 2026](https://arxiv.org/abs/2602.12670)) and Dong et al. ([2026](https://arxiv.org/abs/2608.11888)) show focused skills deliver +16.6 pp gains while bloated procedural bundles trigger task-implementation faults. Pinned, CI-compiled Effect v4 + Reylo modules directly counter GitChameleon API drift ([Islah et al., 2024](https://arxiv.org/abs/2411.05830)) and Spracklen package hallucinations ([Spracklen et al., 2025](https://arxiv.org/abs/2406.10279)).
4. **Pair executable tests with a narrow SAST/lint rulepack and an optional fresh-context adversarial audit pass.**
   - Ban syntactic footguns deterministically in CI (unsafe equality on secrets, weak hashes, `Math.random`, hardcoded secrets, missing cookie flags) and reserve multi-pass agent review for subtle app-specific authorization boundaries that generic tests cannot see.
