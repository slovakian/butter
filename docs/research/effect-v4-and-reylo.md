# Effect v4 and Reylo: Primary-Source Technical Realities for Butter

*Research date: 2026-11-24 · Ticket: [slovakian/butter#89](https://github.com/slovakian/butter/issues/89)*

This note audits the current primary-source state of **Effect v4** (`effect@4.1.5`) and **Reylo** (`reylo@0.8.3`) for Butter's official PostgreSQL reference code and target auth systems. Every claim below is traced to first-party source code, official migration guides, or npm registry metadata.

---

## Executive Summary & Headline Corrections

Several assumptions from early Effect v4 beta (`effect-smol`) and pre-launch Reylo discussions are **now outdated**:

1. **Effect v4 is GA (`effect@4.1.5`), and beta-era APIs changed before GA:**
   - `Effect-TS/effect-smol` was merged into `Effect-TS/effect`; `effect@4.0.0` shipped `2026-10-01`, `4.1.0` on `2026-10-29`, and `4.1.5` on `2026-11-20` ([GitHub releases](https://github.com/Effect-TS/effect/releases)).
   - **`ServiceMap.Service` does not exist in GA Effect v4.** Services use **`Context.Service`** (`Context.Service<Self, Shape>()(id)`), and `Effect.Service` / `Context.Tag` / `Effect.Tag` were replaced by `Context.Service` + explicit `Layer.effect` ([`migration/services.md`](https://github.com/Effect-TS/effect/blob/main/migration/services.md)).
   - **`effect/unstable/*` paths were removed with no compatibility exports.** Modules moved to `effect/http`, `effect/http-api`, `effect/rpc`, `effect/sql`, `effect/crypto`, `effect/jose`, etc., and declare stability via JSDoc **`@stability unstable`** ([`MIGRATION.md`](https://github.com/Effect-TS/effect/blob/main/MIGRATION.md)).
   - **`Schema.TaggedErrorClass` was removed.** Use **`Schema.TaggedError`** or **`Schema.Error`** (both `@stability stable`) or **`Data.TaggedError`** for internal non-serialized errors ([`migration/v3-to-v4.md`](https://github.com/Effect-TS/effect/blob/main/migration/v3-to-v4.md), [`packages/effect/src/Schema.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/Schema.ts)).
   - **`effect/crypto` (including `Password`, added in `4.1.5`) and `effect/jose` (added in `4.1.1`) now exist inside `effect` with zero runtime dependencies**, but are **`@stability unstable`** (minor releases may break them).
2. **Reylo (`0.8.3`, repo created `2026-10-21`) is fast-moving pre-1.0, requires TypeScript 7.1 nightly + Node 24+ for direct `.sql` imports, DOES include migrations, and is NOT directly compatible with `@effect/sql-pg`:**
   - Direct `.sql` imports rely on **TypeScript 7.1 content mappers** (`typescript` `latest` is still `7.0.2`; `7.1.0-beta` / `typescript@next` nightly `>= 2026-11-12` is required) plus `tsc --noEmit --runExternalCode` and a runtime hook (`node --import reylo/register` or bundler plugin) ([`reylosql/reylo/README.md`](https://github.com/reylosql/reylo/blob/main/README.md)).
   - **Codegen escape hatch exists:** `npx reylo generate typescript 'src/queries/**/*.sql' --out src/queries.ts` emits a single TypeScript file that needs **no TS 7.1, no content mapper, and no bundler plugin** ([`site/content/sections/08c-codegen.mdx`](https://github.com/reylosql/reylo/blob/main/site/content/sections/08c-codegen.mdx)).
   - **Reylo Migrate ships in `v0.8`:** SQL-first declarative `reylo/schema.sql` diffing, lockfile (`reylo.lock`), and `reylo migrate {init,new,dev,deploy}` are built in, alongside full compatibility with external migration tools ([`site/content/docs/migrate.mdx`](https://github.com/reylosql/reylo/blob/main/site/content/docs/migrate.mdx)).
   - **Incompatible with `@effect/sql-pg`:** Effect v4's `@effect/sql-pg` uses its own native wire-protocol client (`PgPool`), which Reylo `.run()` rejects (`src/execute.ts`). Butter should wrap a standard supported Postgres driver (`pg` or `postgres.js`) in a small `Context.Service` rather than using `@effect/sql-pg`.

## 1. Effect v4 Technical Realities (`effect@4.1.5`)

### 1.1 Release Status, Package Structure & Stability Tiers

- **Current release:** `effect@4.1.5` (published `2026-11-20`; `4.0.0` published `2026-10-01`; `3.22.5` remains on the `prev` npm dist-tag). All `@effect/*` packages release in lockstep under the same version (`@effect/platform-node@4.1.5`, `@effect/sql-pg@4.1.5`, `@effect/vitest@4.1.5`) ([`MIGRATION.md`](https://github.com/Effect-TS/effect/blob/main/MIGRATION.md), [npm registry `effect`](https://registry.npmjs.org/-/package/effect/dist-tags)).
- **Single-package consolidation:** Core `effect` has **zero runtime dependencies** (`dependencies: null`) and bundles modules previously split across `@effect/platform`, `@effect/rpc`, `@effect/sql`, and `@effect/cluster`. Separate packages remain only for runtime/driver/provider bindings (`@effect/platform-node`, `@effect/platform-bun`, `@effect/platform-cloudflare`, `@effect/platform-browser`, `@effect/sql-pg`, `@effect/opentelemetry`, `@effect/vitest`) ([`packages/effect/package.json`](https://github.com/Effect-TS/effect/blob/main/packages/effect/package.json)).
- **Stability semantics matter for Butter:** Effect v4 enforces JSDoc `@stability` tiers ([`MIGRATION.md`](https://github.com/Effect-TS/effect/blob/main/MIGRATION.md)):
  - **`@stability stable`** (strict semver): `Effect`, `Layer`, `Context`, `Schema` (core `effect/Schema`), `Data`, `Clock`, `Random`, `Redacted`, `Cause`, `Exit`, `Stream`.
  - **`@stability unstable`** (features in patches, **breaking changes allowed in minor releases**, e.g. `4.1` -> `4.2`): `effect/http`, `effect/http-api`, `effect/rpc`, `effect/sql`, `effect/crypto`, `effect/jose`, `effect/schema` (extra subpath), and **all modules in non-`effect` packages** (`@effect/platform-node`, etc.).
  - **`@stability experimental`**: breaking changes allowed in patch releases.

### 1.2 Services, Layers, and Runtime Patterns

- **`Context.Service` replaces all v3 service APIs** (`Context.Tag`, `Context.GenericTag`, `Effect.Tag`, `Effect.Service`) ([`migration/services.md`](https://github.com/Effect-TS/effect/blob/main/migration/services.md)):
  - Function form: `const Db = Context.Service<Db>("Db")`
  - Class form: `class Db extends Context.Service<Db, { readonly query: ... }>()("Db") {}` (note reversed generic/id order vs v3's `Context.Tag(id)<Self, Shape>()`).
  - `make` form: `class Auth extends Context.Service<Auth>()("Auth", { make: Effect.gen(...) }) { static readonly layer = Layer.effect(this, this.make).pipe(Layer.provide(...)) }`. Unlike v3 `Effect.Service`, `dependencies` and auto-generated `.Default` layers are gone — layers are wired explicitly and named `layer` (plus `layerTest`, etc.).
  - Static proxy accessors (`Effect.Tag`) are removed; use `yield* Service` inside `Effect.gen` (preferred) or `Service.use(fn)` / `Service.useSync(fn)`.
  - **`Context.Reference`** replaces `FiberRef` for default-valued contextual config (`Context.Reference<T>("Id", { defaultValue })`) ([`migration/services.md`](https://github.com/Effect-TS/effect/blob/main/migration/services.md)).
- **Error-handling combinator renames:** `catchAll` -> `catch`, `catchAllCause` -> `catchCause`, `catchAllDefect` -> `catchDefect`, `catchSome` -> `catchFilter`, plus new `Effect.catchReason` / `Effect.catchReasons` for nested reason errors (used by `CryptoError`, `HttpClientError`, etc.). Critically, **defects now take precedence in mixed causes** across *all* typed recovery operators (`catchTag`, `catchTags`, `catchIf`, etc.) so a finalizer defect is never silently swallowed ([`migration/error-handling.md`](https://github.com/Effect-TS/effect/blob/main/migration/error-handling.md)).

### 1.3 Schema v4 and Typed Errors (`Schema.TaggedError` vs `Data.TaggedError`)

- **Core `effect/Schema` is `@stability stable`**, with significant breaking changes from v3 ([`migration/schema.md`](https://github.com/Effect-TS/effect/blob/main/migration/schema.md)):
  - Variadic constructors became arrays: `Schema.Union([A, B])`, `Schema.Tuple([A, B])`, `Schema.Literals(["a", "b"])`.
  - Decoding/encoding functions renamed: `decodeUnknownEffect`, `encodeUnknownEffect`, `decodeUnknownExit` (no `Either` — `Either` became `Result`).
  - Filters use `.check(Schema.isMinLength(...))`, `Schema.isUUID()`, `Schema.isPattern(...)`; `annotations` -> `annotate`; `transform` -> `decodeTo(..., SchemaTransformation.transform(...))`.
  - **Sharp auth trap:** `Schema.Date` is now v3's `DateFromSelf` (expects a `Date` instance, **not** an ISO string); ISO strings use `Schema.DateFromString`. Similarly, `Schema.Redacted(S)` is v3's `RedactedFromSelf`; wrapping a raw string secret into `Redacted` is now **`Schema.RedactedFromValue(Schema.String)`** ([`migration/schema.md`](https://github.com/Effect-TS/effect/blob/main/migration/schema.md#L96-L160)).
  - **Interoperability:** `Schema.toStandardSchemaV1` exposes Standard Schema v1 for framework/form validators without forcing clients onto Effect.
- **Typed Error Classes:**
  - **`Schema.TaggedError`** (`packages/effect/src/Schema.ts:18025`, `@stability stable`): yieldable `Error` subclass with `_tag`, schema validation, and JSON/wire serialization (`class InvalidCredentials extends Schema.TaggedError<InvalidCredentials>()("InvalidCredentials", { ... }) {}`). Use this for **boundary/API/RPC errors** that cross HTTP or RPC wires.
  - **`Schema.Error`** (`packages/effect/src/Schema.ts:17964`, `@stability stable`): untagged yieldable schema error (used by `HttpApiError` built-ins with explicit `_tag: Schema.tag(...)` + `httpApiStatus` annotations).
  - **`Data.TaggedError`** (`packages/effect/src/Data.ts:777`, `@stability stable`): lightweight yieldable tagged error without schema serialization overhead. Use for **internal server-only domain/DB errors** that must never leak verbatim over the wire.
  - `Schema.TaggedErrorClass` was removed ([`migration/v3-to-v4.md`](https://github.com/Effect-TS/effect/blob/main/migration/v3-to-v4.md)).

### 1.4 Clock, Random, `effect/crypto`, and `effect/jose`

- **`Clock` (`@stability stable`) & `TestClock` (`effect/testing`)**: `Clock.currentTimeMillis`, `Clock.currentTimeNanos`, `Clock.monotonicTimeNanos`, `Clock.sleep`. Essential for deterministic session-expiry, token-TTL, and rate-limit tests via `TestClock` ([`Clock.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/Clock.ts)).
- **`Random` (`@stability stable`) — NOT cryptographically secure:** `effect/Random` explicitly warns its default implementation uses `Math.random` and must **never** be used for tokens, salts, nonces, or secrets ([`Random.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/Random.ts)).
- **`effect/crypto` (`@stability unstable`, zero runtime dependencies):** Ships a surprisingly complete, auth-relevant crypto suite inside `effect` ([`crypto/index.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/crypto/index.ts)):
  - **`SecureRandom`** (`@since 4.0.0`): `randomBytes`, unbiased `intBetween`, `shuffle`, `uuidV4`, monotonic `uuidV7`, monotonic `ulid` (explicitly warns `uuidV7`/`ulid` reveal ordering and must not be used as secrets) ([`SecureRandom.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/crypto/SecureRandom.ts)).
  - **`Password`** (`@since 4.1.5` — brand new!): PHC-format password hashing (`hash`, `verify`, `needsRehash`, `encode`, `decode`) accepting `string | Redacted.Redacted`, using `Mac.timingSafeEqual` ([`Password.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/crypto/Password.ts)).
    - **Sharp edges:** Supports **only Argon2id (v=19) and PBKDF2** (`bcrypt` and `scrypt` are explicitly rejected by `Password.decode`). There is no default algorithm (`Password.layer({ algorithm })` requires explicit choice). **Argon2id requires `NodeCrypto.layerKdf` from `@effect/platform-node`, which requires Node.js `>= 24.7` or Bun `>= 1.4`**; `Kdf.layerWebCrypto` fails with `Unsupported` for Argon2id ([`Kdf.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/crypto/Kdf.ts), [`NodeCrypto.ts`](https://github.com/Effect-TS/effect/blob/main/packages/platform/node/src/NodeCrypto.ts)). Passwords are UTF-8 encoded without Unicode normalization.
  - **`Digest`** (SHA-256/384/512 via WebCrypto; MD5 vendored from `@noble/hashes` 2.4.0), **`Mac`** (HMAC-SHA* + `timingSafeEqual`), **`Aead`** (AES-GCM via WebCrypto; ChaCha20/XChaCha20-Poly1305 vendored from `@noble/ciphers` 2.4.0 or `node:crypto` via `NodeCrypto.layerAead`), **`Signature`** (Ed25519, ECDSA P-256/384/521, RSA-PSS/PKCS1), **`Kdf`** (HKDF, PBKDF2, Argon2id).
- **`effect/jose` (`@stability unstable`, `@since 4.1.1`, zero deps):** Compact JWS/JWE/JWT (`HS256/384/512`, `RS*/PS*/ES*`, `EdDSA`, `dir`/A256GCM), schema-typed `Jwt` claims, and `Jwks.layerLocal` / `Jwks.layerRemote` with caching (useful for OIDC ID token verification without third-party `jose` if desired; note JSDoc warns apps must enforce their own token-length limit before verify/decode) ([`jose/index.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/jose/index.ts), [`jose/Jwks.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/jose/Jwks.ts)).
- **Risk for Butter:** Both `effect/crypto` and `effect/jose` are `@stability unstable`, and `Password` landed just 5 days ago (`4.1.5`). Butter should isolate password hashing and token crypto behind narrow target-app interfaces/services so minor-version signature churn in `effect/crypto` stays localized to one file.

### 1.5 HTTP (`effect/http`, `effect/http-api`), RPC (`effect/rpc`) & Error Serialization

- **All three modules (`effect/http`, `effect/http-api`, `effect/rpc`) are `@stability unstable`** ([`MIGRATION.md`](https://github.com/Effect-TS/effect/blob/main/MIGRATION.md)).
- **`effect/http` basics for auth:**
  - `Cookies` provides typed cookie creation, `Set-Cookie` serialization, expiry (`expireCookie`), and `Cookie` header parsing (`HttpOnly`, `Secure`, `SameSite`, etc.) ([`http/Cookies.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/http/Cookies.ts)).
  - `HttpRouter.toWebHandler` bridges Effect HTTP servers directly to Web Standard `(Request) => Promise<Response>` handlers (Next.js Route Handlers, Cloudflare Workers, Bun, Deno, Node) ([`http/HttpRouter.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/http/HttpRouter.ts)).
  - `ProblemDetails` (`@since 4.0.6`) implements RFC 9457 `application/problem+json` ([`http/ProblemDetails.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/http/ProblemDetails.ts)).
- **`effect/http-api` error & auth contract:**
  - Endpoints declare typed `Schema.TaggedError` / `Schema.Error` errors annotated with HTTP status codes (`HttpApiSchema.status(401)` or `httpApiStatus: 401`), `HttpApiSchema.asNoContent(...)`, or RFC 9457 `HttpApiSchema.asProblem(...)` ([`HttpApiSchema.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/http-api/HttpApiSchema.ts), [`HttpApiError.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/http-api/HttpApiError.ts)).
  - `HttpApiSecurity` models `http`/`bearer`, `basic`, and `apiKey` (`in: "header" | "query" | "cookie"`), wired via `HttpApiMiddleware.Service` with `security` to provide a typed `CurrentUser`/`Session` service into handlers ([`HttpApiSecurity.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/http-api/HttpApiSecurity.ts), [`HttpApiMiddleware.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/http-api/HttpApiMiddleware.ts)).
  - **Client error serialization:** `HttpApiClient` encodes requests and decodes responses by `(HTTP status code, Content-Type)` back into the exact typed error union declared on the endpoint/middleware, plus `HttpClientError` and `Schema.SchemaError` on transport/mismatch failures ([`HttpApiClient.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/http-api/HttpApiClient.ts)). Uncaught defects become `500` without leaking internal details; invalid inputs become `HttpApiSchemaError` (`400`).
  - **Crucial non-Effect client compatibility:** Because `HttpApi` speaks standard HTTP + JSON/RFC 9457 + generates OpenAPI via `OpenApi.fromApi`, **plain `fetch` / TanStack Query / React Server Actions / mobile clients can consume an Effect `HttpApi` server without importing `effect` on the client at all.**
- **`effect/rpc` error serialization:**
  - Each `Rpc` declares `payloadSchema`, `successSchema`, `errorSchema`, and `defectSchema`. On the wire (`RpcServer` -> `RpcClient` over HTTP, WebSocket, worker, or socket; JSON, NDJSON, JSON-RPC, or `SchemaBinary`), the server encodes the full `Exit` (`Rpc.exitSchema(rpc)`) including typed failures, defects, and interrupts ([`Rpc.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/rpc/Rpc.ts), [`RpcServer.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/rpc/RpcServer.ts), [`RpcSerialization.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/rpc/RpcSerialization.ts)).
  - `RpcMiddleware` inspects request `headers` (including cookies/bearer headers) and provides auth context to handlers ([`RpcMiddleware.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/rpc/RpcMiddleware.ts)).
  - **Auth caveat for `effect/rpc`:** Unlike standard REST/HTTP endpoints, RPC over HTTP/WS carries an Effect-specific envelope (`Exit`/chunk framing) unless using `layerJsonRpc`, requires `effect` + `effect/rpc` on the client for typed consumption, and does **not** naturally fit browser-redirect flows (OAuth callbacks, magic-link GET endpoints, cookie-setting redirects). Auth transport in Butter should treat HTTP endpoints as primary (with `HttpApi` or `HttpRouter`) and `effect/rpc` as an optional app-level consumer of the same Effect auth services.

### 1.6 Client-Side Bundle Size Reality

- Effect v4 was rebuilt for tree-shaking (`packages/effect/package.json` marks only `SchemaJITCompiler/enable.js` as having `sideEffects`, and builds with `babel --plugins annotate-pure-calls`).
- Primary-source benchmark from [`MIGRATION.md`](https://github.com/Effect-TS/effect/blob/main/MIGRATION.md#L71-L75): **a minimal Effect v4 program bundles to `7.1 kB` minified + gzipped** (~5× smaller than Effect v3's ~35.6 kB).
- **However**, pulling `Effect` + `Schema` + `HttpClient`/`HttpApiClient` or `RpcClient` into a browser bundle still ships the Effect runtime + Schema interpreter/codecs (notice `packages/tools/bundle/fixtures/` tracks `basic.ts`, `schema.ts`, `http-client.ts`, etc. separately because each adds weight).
- **Architectural takeaway for Butter:** Server-side Effect v4 is lightweight and zero-dep, while **browser clients should NOT be forced to bundle Effect** just to sign in or read session state. Keep the HTTP wire contract clean JSON/cookies/RFC 9457 (or Standard Schema / OpenAPI types) so React/Vue/Next/Svelte clients can call auth with plain `fetch` (~0 kB runtime overhead), while Effect-everywhere teams can optionally use `HttpApiClient` or `RpcClient`.

## 2. Reylo Technical Realities (`reylo@0.8.3`, `reylosql/reylo`)

### 2.1 Current State & Maturity Profile

- **Age & velocity:** `reylosql/reylo` (MIT license, by Colin McDonnell / Reylo) was created **`2026-10-21`** and is at **`0.8.3`** (published `2026-11-23`; `0.9.0` PR `#444` and breaking spec PR `#420` already open, 1,668 stars, 457 issues/PRs in ~34 days) ([GitHub repo](https://github.com/reylosql/reylo), [releases](https://github.com/reylosql/reylo/releases)).
- **Architecture:** A native Rust analysis/migration engine distributed via platform-specific npm `optionalDependencies` (`@reylosql/engine-{darwin,linux,win32}-{arm64,x64}{,-musl}`) plus standalone CLI binaries (Homebrew/curl/Scoop/Docker). Zero runtime JS dependencies; `slonik` is an optional peer dep ([`package.json`](https://github.com/reylosql/reylo/blob/main/package.json)). **CI trap:** never run `npm ci --omit=optional` or the native engine binary is missing ([`site/content/docs/deployment.mdx`](https://github.com/reylosql/reylo/blob/main/site/content/docs/deployment.mdx)).
- **Maturity assessment:** Very capable and rapidly iterated, **pre-1.0 with breaking changes across minor releases** (`0.8.0` had breaking changes from `0.7`; `0.8.3` had minor surfacing changes from `0.8.2`; `0.9.0` is queued).

### 2.2 How `.sql` Imports Work: Tooling, TypeScript 7.1, Runtime & Codegen Escape Hatch

- **Zero-codegen `.sql` imports require bleeding-edge TypeScript 7.1 (not yet GA):**
  - On npm as of `2026-11-24`, `typescript@latest` is **`7.0.2`**, while `7.1` is **`7.1.0-beta`** / **`typescript@next`** (`7.1.0-dev.20261124.1`). Reylo's `README.md` explicitly requires **TypeScript 7.1 nightly `>= 2026-11-12`** (Reylo's own `package.json` pins `^7.1.0-dev.20261118.1`) and **Node 24+** ([`README.md`](https://github.com/reylosql/reylo/blob/main/README.md), [`package.json`](https://github.com/reylosql/reylo/blob/main/package.json)).
  - Powered by TypeScript 7.1 **content mappers** ([`microsoft/typescript-go#4712`](https://github.com/microsoft/typescript-go/pull/4712)): `"contentMappers": [{ "package": "reylo" }]` in `tsconfig.json`, invoked via `tsc --noEmit --runExternalCode`.
  - **Editor friction:** VS Code and Cursor require the **TypeScript 7** (`TypeScriptTeam.native-preview`) extension explicitly pointed at `./node_modules/typescript` (the extension's bundled 7.0 lacks content mappers), plus Workspace Trust enabled and `DATABASE_URL` inside `.env` (editors don't inherit shell env). Zed requires custom `typescript-ls` config and **cannot display `.sql` diagnostics inside `.sql` files** (only during `tsc`) ([`site/content/sections/01-setup.mdx`](https://github.com/reylosql/reylo/blob/main/site/content/sections/01-setup.mdx#L416-L496)).
  - **Runtime loading:** `.sql` is not native JS. At runtime you must use `node --import reylo/register` or one of Reylo's bundler/test plugins (`reylo/vite`, `reylo/next`, `reylo/esbuild`, `reylo/rollup`, `reylo/rolldown`, `reylo/webpack`, `reylo/turbopack`, `reylo/jest`) ([`README.md`](https://github.com/reylosql/reylo/blob/main/README.md)).
  - **Live database required at type-check AND build time:** Both `tsc` and bundler plugins connect to a live Postgres database (`DATABASE_URL` or `direct_url` in `.reylo.yaml`) to `PREPARE` queries and inspect `pg_catalog`. Offline/cached builds work only if `reylo/.cache/` (gitignored) is warm; platforms that build before migrating (e.g. Vercel) must spin up an ephemeral DB, apply migrations, build, and tear it down ([`site/content/docs/deployment.mdx`](https://github.com/reylosql/reylo/blob/main/site/content/docs/deployment.mdx), [`site/content/sections/09-faq.mdx`](https://github.com/reylosql/reylo/blob/main/site/content/sections/09-faq.mdx)).
- **Codegen escape hatch (`reylo generate typescript`) — HUGE for adoption:**
  - `npx reylo generate typescript 'src/queries/**/*.sql' --out src/queries.ts` compiles all `.sql` files into one flat TypeScript file with camelCase exports (`getUser`, `getUser.Params`, `getUser.Row`).
  - **It requires NO TypeScript 7.1, NO content mapper, NO bundler plugin, and NO `reylo/register` preload** ([`site/content/sections/08c-codegen.mdx`](https://github.com/reylosql/reylo/blob/main/site/content/sections/08c-codegen.mdx)). Tradeoff: filenames must be globally unique across directories (collisions fail generation) and agents must re-run generation after editing `.sql` files (CI verifies via `git diff --exit-code`).

### 2.3 Migrations Support (`reylo migrate`)

- **Reylo DOES ship a full SQL-first migration tool** (introduced in `v0.8.0`, improved through `v0.8.3`) ([`site/content/docs/migrate.mdx`](https://github.com/reylosql/reylo/blob/main/site/content/docs/migrate.mdx), [`site/content/docs/migrate-usage.mdx`](https://github.com/reylosql/reylo/blob/main/site/content/docs/migrate-usage.mdx)):
  - **Declarative `reylo/schema.sql` + imperative SQL migrations:** Edit `reylo/schema.sql` (standard Postgres DDL — tables, constraints, partial/expression/concurrent indexes, triggers, functions, enums, domains, RLS policies, extensions, grants), run `reylo migrate new <name>` to diff and emit plain editable `.sql` migration files, `reylo migrate dev` to apply locally, `reylo migrate deploy` in production (or `import { migrate } from "reylo"` programmatically).
  - **Safety features:** Refuses ambiguous drops/renames until disambiguated with `--drop` / `--rename`; tracks chained checksums in `reylo/reylo.lock` (or lock-free mode with shadow-DB order-independence replay); handles concurrent deploys safely (`v0.8.3` fixed `create index concurrently` deadlocks); `reylo migrate init` works on existing Postgres DBs without requiring `pg_dump` (`v0.8.3`).
  - **Also migration-tool agnostic:** Teams can ignore `reylo migrate` and use Prisma Migrate, Drizzle Kit, or plain SQL files — just exclude migration folders in `tsconfig.json` (`"exclude": ["db/**"]` or `"reylo/migrations/**"`) because multi-statement `.sql` files and DDL fail query type-checking ([`skills/reylo/SKILL.md`](https://github.com/reylosql/reylo/blob/main/skills/reylo/SKILL.md)).
  - **Active sharp edges:** Still actively hardening on Postgres DDL edge cases (e.g., open issue [`#456`](https://github.com/reylosql/reylo/issues/456) on literal `\r` in `CHECK` constraints; `migrate` requires a direct Postgres connection, refusing transaction poolers like Neon `-pooler` or Supabase port 6543; operators/casts/text-search configs are name-compared only).

### 2.4 PostgreSQL Support, Drivers & Effect SQL Compatibility

- **Supported Postgres drivers** ([`src/execute.ts`](https://github.com/reylosql/reylo/blob/main/src/execute.ts), [`site/content/docs/postgres.mdx`](https://github.com/reylosql/reylo/blob/main/site/content/docs/postgres.mdx)):
  - `pg` (`Pool`, `Client`, `PoolClient` — **not** `binary: true` or `pg.native`), `postgres.js` (`sql`, `tx`, `savepoint`, `reserve` — **not** `transform.row`), `Bun.sql` (use Bun `>= 1.4.4` to avoid timestamp microsecond/array bugs), `PGlite`, `@neondatabase/serverless`, `pg-promise`, `slonik >= 49.12.0`, `@vercel/postgres`, Drizzle Postgres / Drizzle over supported drivers, Knex over `pg`.
  - **Driver-wrapper trap:** `.run()` inspects the client shape and **refuses hand-written wrapper objects** around a pool; any wrapper must subclass or `Proxy` a real driver client ([`skills/reylo/SKILL.md`](https://github.com/reylosql/reylo/blob/main/skills/reylo/SKILL.md)).
  - **PgBouncer / transaction-pooler trap:** With `postgres.js` behind PgBouncer in transaction mode, pass `prepare: false`. With `postgres.js` or `Bun.sql` on queries with optional filters, set `connection: { plan_cache_mode: "force_custom_plan" }` or Postgres may switch to a full-table-scan generic plan after 5 runs ([`site/content/docs/postgres.mdx`](https://github.com/reylosql/reylo/blob/main/site/content/docs/postgres.mdx#L877-L904)).
- **Compatibility with `@effect/sql-pg`: NOT DIRECTLY COMPATIBLE.**
  - Effect v4's `@effect/sql-pg` uses its own native PostgreSQL wire-protocol pool (`PgPool`) rather than wrapping `pg` or `postgres.js` ([`packages/sql/pg/src/PgClient.ts`](https://github.com/Effect-TS/effect/blob/main/packages/sql/pg/src/PgClient.ts)). Its `PgClient` is not in Reylo's `PostgresClient` union and will be rejected by `.run()`.
  - Reylo does expose a **`StandardQueryV1`** (`query["~standard"].query` with `text`, `encode`, `decode`, `columns`, `cardinality`) ([`src/standard-query.ts`](https://github.com/reylosql/reylo/blob/main/src/standard-query.ts)), which could theoretically bridge a custom driver if `@effect/sql-pg` exposed raw unparsed text rows, **but Effect SQL does not implement Standard Query**.
  - **Cleanest path for Butter:** Do **not** depend on `@effect/sql-pg` when using Reylo. Provide a tiny `Context.Service` (`Db`) holding a `pg.Pool` or `postgres.js` client (with a scoped transaction helper wrapping `db.begin` / `pool.connect` in `Effect.tryPromise` + `query.try(client, params)`).

### 2.5 Query Typing, Dynamic Queries, Joins & Error Ergonomics

- **Deterministic cross-driver value types (important for Effect Schema interop!):**
  - Reylo bypasses driver type parsers and decodes every value itself ([`site/content/docs/postgres.mdx`](https://github.com/reylosql/reylo/blob/main/site/content/docs/postgres.mdx#L68-L268)):
    - **`timestamptz` -> UTC ISO 8601 `string` with 6 microsecond digits (`"2026-10-20T08:00:00.123456Z"`) — NEVER a `Date`!** (Pairs cleanly with `Schema.DateFromString` or `Temporal.Instant.from`, avoiding `Date` millisecond truncation and timezone bugs.)
    - **`bigint` / `bigserial` / `count(*)` -> `bigint`** (cast `count(*)::int` in SQL if returning JSON, since `JSON.stringify` throws on `bigint`).
    - **`bytea` -> `Uint8Array`** (ideal for session token hashes, WebAuthn credential IDs/public keys!).
    - **`uuid`, `text`, `numeric` -> `string`**; Postgres enums and `CHECK (col IN (...))` -> **TypeScript string literal unions**; `jsonb` with a JSON Schema `CHECK` -> **typed object shape**.
- **Cardinality & nullability inference:** Primary/unique key lookups and `LIMIT 1` infer `Row | null`; ungrouped aggregates and single-row `INSERT ... RETURNING` infer `Row`; writes without `RETURNING` infer `void`; everything else `Row[]`. Note: a **`BEFORE` row trigger** on a table makes `INSERT/UPDATE ... RETURNING` nullable unless Reylo proves every PL/pgSQL `RETURN` returns the row ([`skills/reylo/SKILL.md`](https://github.com/reylosql/reylo/blob/main/skills/reylo/SKILL.md)).
- **Joins & nested fetching (great fit for single-query auth hot paths!):**
  - Standard `JOIN` / `LEFT JOIN` nullability is tracked automatically.
  - One-to-many / one-to-one nested rows use correlated Postgres subqueries: `array(select m from (select ... where user_id = u.id) m) as memberships` (preferred over `jsonb_agg` because `jsonb_agg` rounds `bigint > 2^53` and formats `timestamptz` in session timezone) ([`skills/reylo/SKILL.md`](https://github.com/reylosql/reylo/blob/main/skills/reylo/SKILL.md)).
- **Typed database errors via `.try()` (great fit for Effect error mapping!):**
  - `await createUser.try(db, params)` returns `{ value } | { error }` for Postgres server errors while still throwing transport/connection failures.
  - For queries without triggers/UDFs, **`error.condition`** (`"unique_violation"`, `"foreign_key_violation"`, etc.) and **`error.constraint`** are **statically narrowed to the exact constraint names on the target table** (e.g., `"users_email_key"`) ([`src/query-error.ts`](https://github.com/reylosql/reylo/blob/main/src/query-error.ts)).
  - **Postgres transaction caveat:** A database error inside a transaction still aborts the Postgres transaction even when caught by `.try()`; continuing requires a `SAVEPOINT` ([`site/content/docs/postgres.mdx`](https://github.com/reylosql/reylo/blob/main/site/content/docs/postgres.mdx#L837-L845)).
- **Dynamic query & parameter constraints:**
  - **One SQL statement per `.sql` file.**
  - **Each `:param` may appear only once** in a statement (reuse via `WITH input AS (SELECT :id::uuid AS id)` CTE).
  - **Nullable parameters require explicit `:param::nullable(type)`** (except bare writes to nullable columns); otherwise `.run()` throws at runtime on `null`/`undefined`.
  - **No runtime SQL string composition / query builder:** Dynamic sorting uses `ORDER BY CASE WHEN ...`; dynamic filtering uses a JSON Schema-typed `:filters::jsonb('{...}')` parameter + `WITH input` (`->>`); list filters use `= ANY(:ids::text[])` ([`site/content/sections/03-inference.mdx`](https://github.com/reylosql/reylo/blob/main/site/content/sections/03-inference.mdx#L332-L486)).
- **Known limits & open issues to watch:**
  - **Single dev DB per TS project** ([`#141`](https://github.com/reylosql/reylo/issues/141)) — cannot type-check `.sql` files against two different Postgres schemas in one `tsconfig`.
  - **No branded/nominal types** ([`#22`](https://github.com/reylosql/reylo/issues/22)) — `users.id` and `sessions.id` are both plain `string`/`bigint` unless branded in TypeScript/Effect Schema at the repository boundary.
  - **Silent fallback on deep nesting (>1,000 AST levels)** ([`#457`](https://github.com/reylosql/reylo/issues/457)) and PL/pgSQL functions / views with `INSTEAD` rules / Postgres 19 new syntax — all columns silently fall back to nullable `Row[]`.
  - **Diagnostics hold-back:** While any `.sql` file has an error, `tsc` suppresses downstream `.ts` errors until the SQL error is fixed ([`site/content/sections/01-setup.mdx`](https://github.com/reylosql/reylo/blob/main/site/content/sections/01-setup.mdx#L414)).

## 3. Architectural Constraints & Recommendations for Butter

| Area | Constraint Imposed by Stack | Architectural Recommendation for Butter |
| --- | --- | --- |
| **Effect v4 APIs** | `ServiceMap.Service`, `effect/unstable/*`, and `Schema.TaggedErrorClass` are **obsolete**. | Target **`effect@4.1+`** idioms exclusively: `Context.Service`, `Layer.effect`, `Schema.TaggedError`, `Data.TaggedError`, `effect/http-api`, `effect/crypto`. |
| **Unstable Effect modules** | `effect/http`, `effect/http-api`, `effect/rpc`, `effect/crypto`, `effect/jose` are `@stability unstable` (breaking changes allowed in `4.x` minors). | Isolate crypto (`Password`, `SecureRandom`, `Digest`, `Mac`) and transport adapters behind thin target-app `Context.Service` boundaries so minor upgrades touch 1–2 files. |
| **Password hashing & Node version** | `effect/crypto/Password` Argon2id requires **Node `>= 24.7`** (or Bun `>= 1.4`) via `@effect/platform-node`'s `NodeCrypto.layerKdf`; Reylo requires **Node 24+**. | Standardize Butter's reference environment on **Node `>= 24.7`**; document the Argon2id vs WebCrypto/PBKDF2 runtime split explicitly (and note `Password.decode` rejects legacy `bcrypt`/`scrypt` hashes, so migrating apps need a custom verifier branch). |
| **Reylo + TypeScript 7.1** | Direct `.sql` imports require **TypeScript 7.1 beta/nightly** (`typescript@next`), `--runExternalCode`, runtime register/bundler plugin, and a live Postgres DB in CI/builds. | Support **direct `.sql` imports** in Butter's official reference repo (pinned to TS 7.1 + CI Postgres container) AND explicitly document **`reylo generate typescript`** as the zero-friction path for teams on stable TypeScript 7.0 / 5.x or restricted editors. |
| **Reylo + Effect SQL** | `@effect/sql-pg` uses Effect's native wire client and is **incompatible** with Reylo `.run()`. | Do **not** use `@effect/sql-pg` in Butter's Reylo reference code. Provide a minimal `Db` `Context.Service` over `postgres.js` (with `plan_cache_mode: "force_custom_plan"` and `prepare: false` pooler note) or `pg.Pool`, converting Reylo `.try()` constraint errors into typed `Data.TaggedError`s. |
| **Reylo value types -> Effect** | Reylo returns `timestamptz` as UTC ISO `string` (never `Date`), `bytea` as `Uint8Array`, `bigint` as `bigint`, and no nominal brands. | Design auth SQL schemas around `uuid`/`text` IDs, `bytea` for raw token hashes/WebAuthn keys, `timestamptz` compared directly in SQL (`expires_at > now()`) or parsed via `Schema.DateFromString` / `DateTime`, and cast `count(*)::int` where JSON-serialized. |
| **HTTP vs RPC & client bundles** | `effect/http-api` works with standard HTTP/cookies/OpenAPI/RFC 9457; `effect/rpc` needs Effect on the client and doesn't fit browser OAuth/redirect flows. | Make **standard HTTP (`effect/http-api` or `effect/http` + `HttpRouter.toWebHandler`)** Butter's primary auth boundary so non-Effect frontends pay **0 kB** client bundle tax; treat `effect/rpc` and `HttpApiClient` as optional typed consumers for Effect-everywhere teams. |
| **Migrations ownership** | `reylo migrate` is feature-rich on Postgres (`v0.8.3`) but very young (~1 month old, pre-1.0); Reylo queries work with any migration runner. | Ship Butter's reference schema as clean, standard PostgreSQL DDL (`schema.sql`) compatible with `reylo migrate`, Drizzle Kit, Prisma Migrate, or plain SQL migrations — never couple Butter's auth SQL to a single migration runner. |
